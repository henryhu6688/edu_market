

### 基于 EduMarket 的自研 Agent 对话引擎

通过自研 Agent 对话引擎实现智能客服与售后咨询，并解决了买家售前资料了解与卖家推广之间的沟通鸿沟——买家通过自然语言对话即可搜索资料、查阅文档、了解评价、完成下单，卖家无需逐一回复咨询。引擎采用 Tool Calling + Workflow 混合模式，自研实现未依赖 LangChain 等框架。

**个人工作：**

- **设计 7 个业务工具的 Function Calling 编排方案**，针对 LLM 选错工具、编造参数的问题，每轮按模式只暴露允许的工具，描述分"能做什么、不能做什么、何时优先"三段编写，参数约束标注来源，执行前二次校验
- **按场景分流设计**，确定性操作直接走 Workflow 不经 LLM 推理，仅多步决策进入 Agent 循环，避免过度 Agent 化
- **实现 Prompt 模块化设计**，针对导购、答疑、售后三种场景行为策略不同的问题，按角色定义、模式策略、任务状态、用户画像、行为规则、输出格式拆为六个模块按序拼装，模式切换只换策略模块，其余共用
- **实现多层级故障防护与自动恢复**，针对死循环、误调用、执行异常、事实编造等典型故障，通过熔断检测、参数校验、结构化错误码、数据源限定等硬约束逐层兜底
- **设计四层记忆机制**，针对长对话信息丢失、进度断裂、偏好遗忘的问题，短期记忆过滤无效消息，会话状态追踪事实与假设，长期记忆跨会话复用，外部知识按需检索
- **建立离线评估体系**，针对 Agent 行为无法用单元测试覆盖的问题，设计规则检查 + LLM 评分 + 人工抽检三层管道，39 条任务覆盖正常流程、信息缺失、工具故障、越权、多轮干扰

**个人收获：**

- Agent 不可靠的根源是三层叠加：LLM 随机性 × 工具调用不确定性 × 上下文衰减。稳定 Agent 的核心不是 Prompt 技巧，是兜底机制
- 工具设计是 Agent 的地基：描述写清楚比模型能力更重要，参数约束写死来源比 Prompt 更可靠，错误信息结构化比自然语言更有效


### 基于 EduMarket 的 RAG 智能文档问答

面向在线学习场景的 RAG 智能文档问答系统，离线侧实现文档自动解析、切片与向量化入库，在线侧实现语义检索、精排与引用生成。

**个人工作：**

- **实现多格式文档解析与清洗管线**，针对 PDF / DOCX / PPTX 等格式解析复杂度高、不可读文档污染索引的问题，实现自动解析 + 可读性检测 + OCR 降级兜底，不可读拒绝入库，保障索引库质量
- **实现结构感知切分策略**，针对固定窗口切分跨章节语义混杂的问题，按标题层级解析章节树后在边界切分，300-800 字弹性区间，每个切片附带章节路径作为来源标注
- **构建向量+BM25 混合检索**，针对纯向量检索"语义相近但内容不对"的误召回问题，单次查询同时完成 Embedding 相似度与 BM25 关键词打分，RRF 融合排序。VectorStore 接口做存储抽象，支持 MySQL 降级兜底
- **引入 Rerank 精排**，针对 Embedding 召回排序精确率不足的问题，Cross-Encoder 对 Top 10 逐对重排取 Top 3，提升检索结果相关性
- **设计两级缓存策略**，针对 Embedding 与 Rerank 外部 API 调用延迟和成本双高的问题，通过 L1 精确缓存与 L2 语义缓存，API 调用量降低约 50%，端到端延迟大幅降低
- **多层面控制幻觉**，针对 LLM 检索不到内容时自行编造答案的问题，检索结果标注 Source 状态与可信度分级，Prompt 约束仅基于检索内容回答，输出后对关键字段做正则校验与自动修正，附带原文引用供验证

**个人收获：**

- 深刻理解了 Chunk 策略在 RAG 中的前置性——切分质量决定检索天花板。结构感知切分让文档自身层级引导切分边界，比硬套固定窗口更可靠
- 缓存的价值远超预期。两级缓存将外部 API 调用量降低约 50%，端到端延迟从 ~500ms 降至 < 5ms
