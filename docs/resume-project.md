
### 基于 EduMarket 的自研 Agent 对话引擎

通过自研 Agent 对话引擎实现智能客服与售后咨询，并解决了买家售前资料了解与卖家推广之间的沟通鸿沟——买家通过自然语言对话即可搜索资料、查阅文档、了解评价、完成下单，卖家无需逐一回复咨询。

**个人工作：**

- **混合编排模式**：针对纯 ReAct 每步走 LLM、确定性操作浪费 token 的问题，采用 ReAct + Workflow 混合架构——确定性操作走 Workflow 直接执行，多步决策进 ReAct 自主规划，兼顾灵活与效率
- **工具体系设计**：针对 Tool 设计不当导致调用失控的问题，按搜索/交易/售后/知识四组划分，统一参数 Schema 与错误码规范，模式白名单防跨模式越权调用
- **推理稳定性保障**：针对多步推理链路长、单步异常易级联扩散的问题，设计三层递进防护与结构化错误恢复机制，死循环自动熔断、工具失败 LLM 自主降级重试，故障隔离不向上传导
- **Prompt 工程体系**：针对多模式 Prompt 策略差异大、切换成本高的问题，拆为四静态模块与两动态模块，静态 JSON 热更新、动态运行时生成，模式切换仅替换策略模块
- **四层记忆机制**：针对长对话信息丢失、跨会话知识断裂的问题，设计短期记忆 → 会话状态 → 长期记忆 → 外部知识四层递进记忆，同源新数据自动淘汰旧数据
- **离线评估体系**：针对 Agent 行为无法用单元测试覆盖的问题，搭建规则检查 + LLM 评分 + 人工抽检三层评测管道，覆盖核心场景，保证发版前可验收

**项目难点：**

- **多模式 Prompt 编排复杂性**：三种模式 Prompt 策略差异大、切换需整体替换，模块化拆为四静态两动态，实现跨模式复用与独立热更新
- **多步推理死循环**：LLM 反复调用同一工具陷入死循环，设计精确熔断 → 语义检测 → 硬上限三层递进防护，逐层拦截
- **长对话上下文污染**：早期中间结果过时仍占上下文，设计事实/假设/废弃三层状态管理，同源新数据自动淘汰旧数据


### 基于 EduMarket 的 RAG 智能文档问答

面向在线学习场景的 RAG 文档问答系统，离线侧实现多格式解析、清洗、切片与向量化，在线侧实现混合检索、精排与带来源引用的答案生成。

**个人工作：**

- **多格式文档解析与清洗管线**：针对多格式解析复杂、不可读文档污染索引的问题，自动解析 + 可读性检测 + OCR 降级兜底，不可读拒绝入库
- **结构感知切分策略**：针对固定窗口切分跨章节语义混杂的问题，按标题层级解析章节树后在边界切分，弹性区间 300-800 字，切片附带章节路径作为来源标注
- **向量+BM25 混合检索**：针对纯向量检索语义相近但内容不对的误召回问题，向量与关键词并行打分，RRF 融合排序，VectorStore 接口抽象支持 MySQL 降级
- **Cross-Encoder Rerank 精排**：针对 Embedding 召回排序精度不足的问题，粗召回 Top 20 经 Reranker 逐对重排取 Top 5，从宽泛候选集精确聚焦
- **两级缓存策略**：针对 Embedding 与 Rerank 外部 API 延迟和成本双高的问题，L1 精确缓存 + L2 语义缓存，API 调用量降低约 50%，端到端延迟降至毫秒级
- **多层面控制幻觉**：针对 LLM 检索不到内容时自行编造答案的问题，检索结果标注可信度分级，Prompt 约束仅基于检索内容回答，附带原文引用供验证

**项目难点：**

- **专业术语召回不足**：纯 Embedding 对技术术语语义泛化过强，引入 BM25 关键词检索混合打分，RRF 融合后经 Reranker 逐对精排，关键词命中优先提权
- **Chunk 切分跨段落引用丢失**：固定窗口切分后上下文断裂，按标题层级解析章节树在边界切分，检索时自动拼回章节上下文
- **LLM 输出事实编造**：检索为空时 LLM 自行编造答案，Prompt 注入可信度分级约束仅基于检索内容回答，输出后正则校验修正
- **外部 API 调用成本与延迟双高**：Embedding 与 Rerank 外部调用成本高，Prompt 压缩去冗余 + 语义缓存命中直接返回 + 短文本走小模型分流，API 调用量降低过半，延迟从秒级压至毫秒级
